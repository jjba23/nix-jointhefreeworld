/Everything I maintain, built by Nix: eight programs, seven Guile libraries, five Emacs packages, the icon theme they run under, and the five packages nixpkgs does not have yet./

One flake carrying the whole [[https://jointhefreeworld.org/][Jointhefreeworld]]
collection: Guile programs, Guile libraries, elisp packages, an icon theme, and the
five Guile dependencies nixpkgs has no package for (built from branches of a
[[https://github.com/jjba23/nixpkgs][nixpkgs fork]] until the branches are merged).
One ~flake.lock~ pins every project, so a consumer gets one revision known to
build together instead of twenty-six URLs to keep in step.

Each package is built by the expression in its own repository -- the Guile ones'
~default.nix~, the elisp ones' ~default.nix~ next to the ~.el~ file -- so this
repository never restates how something is built and the two cannot drift apart.
~nix flake check~ builds the whole set and runs every Emacs ERT suite.

*If you use Guix, nothing here is required*: the same projects ship their own
~guix.scm~ and ~manifest.scm~.

* Quick start
:PROPERTIES:
:CUSTOM_ID: quick-start
:END:

#+begin_src shell
nix run git+https://codeberg.org/jjba23/nix-jointhefreeworld#maak -- --help
nix build git+https://codeberg.org/jjba23/nix-jointhefreeworld#guile-veritas
nix profile install git+https://codeberg.org/jjba23/nix-jointhefreeworld#maak
#+end_src

Swap ~maak~ for any name in [[#what-is-here][What is here]].  ~nix run~ works for the
eight programs; the libraries are meant to be built, or to land on Guile's load
path through a shell or a system configuration.

Flakes are behind a flag: put ~experimental-features = nix-command flakes~ in
~/etc/nix/nix.conf~.  There is no ~codeberg:~ flake type, so Codeberg is a plain
~git+https~ URL, as above.  Systems: ~x86_64-linux~, ~aarch64-linux~,
~aarch64-darwin~ (~lambdock~ is wayland-only and stays on linux).

* Use it from your own configuration
:PROPERTIES:
:CUSTOM_ID: use-it-from-your-own-configuration
:END:

#+begin_src nix
{
  inputs.nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
  inputs.nix-jointhefreeworld.url = "git+https://codeberg.org/jjba23/nix-jointhefreeworld";

  outputs = { self, nixpkgs, nix-jointhefreeworld, ... }: {
    nixosConfigurations.example = nixpkgs.lib.nixosSystem {
      system = "x86_64-linux";
      modules = [({ pkgs, ... }: {
        nixpkgs.overlays = [ nix-jointhefreeworld.overlays.default ];
        environment.systemPackages = with pkgs; [ maak guile-veritas ];
      })];
    };
  };
}
#+end_src

Home-manager and nix-darwin take the same overlay through ~nixpkgs.overlays~.

| you write                                                          | you get                                        |
|--------------------------------------------------------------------+------------------------------------------------|
| ~nixpkgs.overlays = [ nix-jointhefreeworld.overlays.default ];~    | every name, replacing nixpkgs' copies          |
| ~nixpkgs.overlays = [ nix-jointhefreeworld.overlays.maak ];~       | one name, nothing else added                   |
| ~nixpkgs.overlays = [ nix-jointhefreeworld.overlays.namespaced ];~ | ~pkgs.jointhefreeworld.maak~, nothing shadowed |

There is a per-package overlay for every name, and each builds against the set's
own definitions, so ~overlays.araneola~ still finds its ~guile-scriba~.

** Emacs packages
:PROPERTIES:
:CUSTOM_ID: emacs-packages
:END:

#+begin_src nix
let
  emacsPackages = pkgs.emacsPackages.overrideScope nix-jointhefreeworld.emacsOverlay;
in
  emacsPackages.withPackages (epkgs: [ epkgs.maak epkgs.veritas ])
#+end_src

With ~overlays.default~ applied, ~pkgs.emacsPackages~ already has the five, so
~pkgs.emacsPackages.withPackages~ is enough: they are built with ~melpaBuild~, so
autoloads and byte code come along and ~(require 'maak)~ works.

** One part only
:PROPERTIES:
:CUSTOM_ID: one-part-only
:END:

#+begin_src shell
nix build 'git+https://codeberg.org/jjba23/nix-jointhefreeworld?dir=emacs#emacs-maak'
nix build 'git+https://codeberg.org/jjba23/nix-jointhefreeworld?dir=guile-deps#guile-dbi'
#+end_src

The repository holds three flakes, each with its own lock: the root one,
~guile-deps~ (the five dependencies) and ~emacs~ (the five elisp packages).  A
~?dir=~ consumer fetches only that part's inputs -- five small elisp repositories,
or five nixpkgs branches -- and never the other half.

* Keeping up to date
:PROPERTIES:
:CUSTOM_ID: keeping-up-to-date
:END:

#+begin_src shell
nix flake update              # move every input of the set
nix flake update maak lambdock  # move two of them
nix flake check               # build it all, run every test
#+end_src

~flake.lock~ is the release: a consumer pins a revision of it and gets exactly the
project revisions listed there.

* Adding a project
:PROPERTIES:
:CUSTOM_ID: adding-a-project
:END:

- *A Guile project*: add the repository as a ~flake = false~ input in
  [[./flake.nix][flake.nix]], add a ~sources~ line
  (~guile-example = { repo = "example"; expr = "default.nix"; };~), then
  ~nix flake lock && nix flake check -L~.  If it installs a program, add its name
  to ~programNames~.
- *A dependency nixpkgs lacks*: the same two steps in
  [[./guile-deps/flake.nix][guile-deps/flake.nix]], plus its name to ~depNames~ in the
  root flake.  It has to come from a branch a pull request can merge, so the entry
  can disappear later.
- *An Emacs package*: a ~default.nix~ next to the ~.el~ file in the package's own
  repository, then an input in [[./emacs/flake.nix][emacs/flake.nix]], a line in ~srcs~,
  a line in ~suites~ if it has an ERT suite, and its name in ~elispNames~ in the
  root.

* Contributing
:PROPERTIES:
:CUSTOM_ID: contributing
:END:

Bugs in ~maak~ or ~lambdock~ belong in that project's repository; packaging bugs,
missing platforms and README corrections belong
[[https://codeberg.org/jjba23/nix-jointhefreeworld][here]].  Run
~nix flake check~ before a pull request -- it builds every package of all three
flakes and runs every elisp suite, which is exactly what CI runs.

* Continuous integration
:PROPERTIES:
:CUSTOM_ID: continuous-integration
:END:

[[./.github/workflows/ci.yml][.github/workflows/ci.yml]] runs ~nix flake check~ once per flake, in
one ~ubuntu-latest~ GitHub Actions job, on every push to ~trunk~ and every pull
request; the badge at the top is that workflow.  There is no binary cache yet,
so a fresh install compiles the Guile bytecode locally.
